# 3D Character Controller

Unity와 C#으로 제작한 3D 캐릭터 컨트롤러 개인 기술 데모입니다.
1차로 이동·점프·낙하·착지를 상태 기반으로 구현했고, 현재는 **기존 컨트롤러 위에 파쿠르 동작을 얹는 2차 확장**을 진행하고 있습니다.

## 2차: 파쿠르 확장

### 확장 계기

1차 버전을 마친 뒤 새 프로젝트를 시작할지 고민했지만, 그러면 또 프로토타입 수준에서 멈출 것 같았습니다. 그래서 이미 만든 컨트롤러의 완성도를 끌어올리는 쪽을 택했습니다.

1차 버전은 Animator, 애니메이션 클립, 루트 모션에 대한 이해가 부족했고 사용할 수 있는 모션도 적었습니다. 파쿠르 컨트롤러 사례를 참고해, **기본 컨트롤러를 다듬고 리팩토링해서 그 위에 파쿠르 동작을 추가할 수 있는 구조**를 만드는 것을 목표로 잡았습니다.

## 주요 구현

* 카메라 기준 3인칭 이동 및 이동 방향 기반 회전
* 걷기 / 달리기

* 낙하 높이에 따른 착지 모션 분기

* Raycast 기반 지면 및 경사 판정
* 상태 기반 행동 관리 및 애니메이션 연동
* 파쿠르 감지·조건 판정 모듈과 파쿠르 전용 상태

## 컨트롤러 구조

```
PlayerController
├─ InputHandler
├─ MovementController
├─ JumpController
├─ GroundDetector
├─ HighFallDetector
├─ PlayerStateMachine
├─ PlayerAnimationController
├─ CameraController
└─ ParkourController          (2차)
   ├─ ParkourDetector
   └─ ParkourConditionChecker
```

`PlayerController`는 각 기능을 직접 처리하지 않고, 모듈을 연결하고 실행 흐름을 조정합니다.
파쿠르 기능도 같은 방식으로 별도 모듈로 분리해, 기존 이동·점프 코드를 크게 고치지 않고 추가할 수 있게 했습니다. 파쿠르 종류는 `ParkourType`으로 구분합니다.

```
PlayerBaseState
├─ PlayerIdleState
├─ PlayerMoveState
├─ PlayerJumpState
├─ PlayerFallState
├─ PlayerLandState
└─ PlayerParkourState        (2차, 파쿠르 공통 기반)
   ├─ PlayerVaultState
   └─ PlayerMantleState
```

`PlayerStateMachine`은 상태 교체(Exit → 교체 → Enter)만 담당하고, 전환 조건은 각 상태가 판단합니다.

## 주요 문제 해결

### 1. Rigidbody → CharacterController 전환 (1차)

* **문제**: 실제 지형 테스트에서 이동·회전·경사면·접지 보정 범위가 계속 늘어났고, 값 하나를 바꿀 때마다 다른 이동 조건을 다시 확인해야 했습니다.
* **판단**: 점프·낙하·착지까지 확장하면 보정 비용이 더 커질 것으로 보고 이동 방식을 전환했습니다.
* **결과**: 입력, 이동 방향 계산, 중력, 지면 판정, 상태 관리 구조는 유지하고 이동 적용부와 실행 흐름만 바꿔 재작성 범위를 줄였습니다.

### 2. 낙하·착지 오판정 (1차)

* **문제**: 경사면이나 낮은 단차에서 접지가 순간적으로 끊겨 `Fall`에 잠깐 들어가거나, 공중에서 착지로 판정되었습니다.
* **해결**: 접지 여부 하나만 쓰지 않고 낙하 시간, 수직 속도, Raycast 지면 판정, `CollisionFlags.Below`를 함께 확인하도록 기준을 바꿨습니다.

### 3. 점프 애니메이션 구조 정리 (2차)

* **문제**: 제자리 점프가 `Jump → InAir → Land` 세 클립으로 나뉘어 있어, 점프 높이와 재생 시점을 조정할 때마다 여러 전환 조건을 함께 고쳐야 했습니다. Any State 중심 전환이라 상태가 늘어날수록 의도치 않은 전환의 원인을 찾기도 어려웠습니다.
* **해결**: 제자리 점프를 단일 클립으로 바꾸고, 일반 점프 전환은 Locomotion에서 각 Jump 상태로 직접 연결했습니다. 제자리 점프 Trigger 호출은 `PlayerJumpState.Enter()`로 모아 중복 호출을 막았습니다.
* **배운 점**: 점프가 자연스러워 보이려면 Transition 설정뿐 아니라 클립 재생 속도, 점프 파워, 실제 체공 시간을 함께 맞춰야 했습니다.

### 4. 점프 파워 분리 (2차)

* **문제**: 제자리 점프와 이동 점프가 `jumpPower` 하나를 공유해서, 한쪽 높이를 바꾸면 다른 쪽도 바뀌었습니다.
* **해결**: 점프 종류별 파워를 분리하고(제자리 4.0 / 이동 6.0), 기존 `TryJump(bool)`는 호환을 위해 남긴 채 점프 종류를 받는 오버로드를 추가했습니다.

### 5. 제자리 점프 후 이동이 잠기는 버그 (2차)

* **문제**: 제자리 점프 후 착지하면 회전은 되지만 수평 이동이 되지 않았습니다. FSM은 `PlayerMoveState`로 정상 복귀한 상태였습니다.
* **범위 좁히기**: 파쿠르 구현 이전 버전으로 롤백해도 같은 문제가 발생해, 파쿠르가 아니라 기존 컨트롤러 내부 문제로 판단했습니다.
* **추적**: `JumpController`와 `PlayerController`에 로그를 추가했습니다. 로그 위치와 추적 순서는 AI의 제안을 참고했습니다.

  ```
  State: PlayerMoveState / Grounded: True / CC Grounded: True
  IsJumping: True / FallLocked: True / HorizontalSpeed: 0.00
  ```
* **원인**: `Move()` 직후에는 접지가 감지되지만, 다음 프레임의 점프 종료 판정에는 `isGrounded = false`가 전달되었습니다. 그래서 `EndJump()`가 호출되지 않아 `IsJumping`이 유지되고, 공중 이동 잠금(Lock + Keep)이 풀리지 않았습니다. 제자리 점프는 보존된 수평 속도가 0이라 입력이 있어도 움직이지 않았습니다.
* **해결**: `Move()` 직후 확인한 접지 결과를 `ControllerGroundedAfterMove`에 저장해, 다음 프레임의 점프 종료와 이동 잠금 판정에 쓰도록 바꿨습니다. `JumpController`의 종료 조건과 FSM 구조는 그대로 두고, 컨트롤러 사이에 전달하는 접지 정보의 기준과 시점만 수정했습니다.
* **검증**: 제자리 점프, Run_Jump, 공중 Lock + Keep, 일반 낙하·착지, 높은 낙하 후 Rolling, Rolling 후 이동까지 회귀 테스트를 통과했습니다.
* **남은 과제**: `Move()` 이후 `isGrounded`가 다시 false가 되는 근본 원인은 아직 규명하지 못했고, 수정 후 같은 문제는 재현되지 않았습니다.
* **배운 점**: FSM이 정상 상태로 돌아와도 하위 컨트롤러의 상태가 어긋나면 다른 기능이 막힐 수 있었습니다. 상태 전환만 고치기보다 실제 이동 결과와 내부 상태를 로그로 비교하는 것이 중요했습니다. 또 원인 추적을 AI 제안에 많이 의존했기 때문에, 지금은 제 가설과 검증 순서를 먼저 적고 AI 제안과 비교하고 있습니다.
